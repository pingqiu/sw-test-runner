Its ordinary approved jobs, capture, output ownership, cancellation and final settlement are unchanged. Do not use the old KV `m01-m02-v1` profile or submit an Azure request.

The scenario's resolved `metadata.seaweed_ec_plan` is the JSON encoding of `EC1aPlan`: Implementation=`go` OR `rust`, Keys1..128, Services=`master`,`filer`,`s3` plus14 distinct holder labels; Ready/Seed/Encode/Capture/WrongByte task labels; S1=[S3read,volumeHTTPread]; Episodes=four distinct independently pinned generation restart labels; S2=four pairs[S3read,volumeHTTPread]. Use one M02 bootstrap/GO/host with Workload=s3 and Transport=http, original hard envelope<=10minutes. Exact install/readback and live lease are prerequisites, not inferred from these data. All jobs must be on m02 and independently pinned; all EC scripts and unchanged chaos_load.py must be installed/read back and included in the independent script scan. Source/product pins and host boots belong in the reviewed lab packet, not invented example addresses in this file.

## Job recipe (all argv data independently pinned by GO)

Each Python job uses executable `/usr/bin/python3.12`, argv beginning `-I,<protected-release>/worker/<leaf>`. No submitted shell, replacement Safety scope or PID argument is accepted by the pack.

- Services: `ec_service.py <JSON>` with root=owned output dir, role=job label, exe+sha256=protected product, args=product argv. The helper execs in-place, never launches a child daemon. Volumes must use exactly their private `--dir=<root>/<label>` (Rust) or `-dir=<root>/<label>` (Go). Master uses `-mdir=<root>/master` and explicit `-peers=none`. Filer uses `-config_dir=<root>`, `-localSocket=<root>/filer.sock`; the helper writes0600 filer.toml/LevelDB under its private dir. Use fourteen distinct private volume HTTP/gRPC ports and ordinary max/volume-size flags. Source program and argv are read back with the policy.
- Ready: `ec_setup.py <JSON>` with root, stage=ready and loopback200 URLs for the declared services; bounded30s, no retrying seed/encode faults. The seed is still a mandatory write, not excused if readiness was insufficient.
- Seed: `ec_chaos.py --config <JSON> --stage seed --manifest <root>/manifest.json --journal <root>/seed.jsonl`. Config carries root, run_id, keys, loopback s3/filer_http URLs. Bucket/payloads come from unchanged chaos_load.py. Every object is256KiB with one FID. A PUT error is UNKNOWN and stops; ACK journal remains even if FID lookup fails. Manifest creation is exclusive0600.
- Encode: `ec_setup.py <JSON>` with root, stage=encode, manifest, protected weed, loopback master endpoint. It invokes the existing pinned product `ec.encode -volumeIds=<ACKed VIDs> -batchSize=0 -shardReplicaPlacement=001`; timeout180s, no reconstruction code or original-file deletion in the harness. Product command failure, remaining original.dat, incomplete shards, or unsupported placement refuses.
- Capture: `ec_capture.py <JSON> <root>/manifest.json`; JSON root/run_id, holders={job:<root>/<job>}, volume_exe and volume_sha256. It finds one actual process per exact executable+dir, captures boot/PID/start, validates product bytes, hashes every .ecNN and .ecx/.vif and checks explicit10+4 EncodeTsNs. First encode only: active/vacuum generations refuse. It checks original.dat absence in all holder dirs. The retained ecx is hashed; object-interval interpretation and reconstructed-path exposure are NOT claimed in1a.
- All read jobs: `ec_chaos.py --config <JSON> --stage read --manifest <root>/manifest.json --route s3|volume --journal <unique-root-file>`. Config also names a loopback `volume` HTTP endpoint on an UNKILLED holder. Each mandatory object has one SUBMIT and one outcome; a wrong/short/error/late outcome fails, no retry/excusal. Routes stay separate.
- WrongByte only: the same read job additionally has `--plant-wrong-byte`. It reads real bytes, XORs the first byte of the first response before digest/verification, and MUST reject that one response while every other read is exact. This is an intentional response-side test control, not a claim of product corruption. Normal jobs are forbidden to carry the flag. Raw captured control output retains the rejected digest/length/status. The control job is not a source of positive integrity credit.
